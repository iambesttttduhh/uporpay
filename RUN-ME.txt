Wake or Lock — an alarm clock you cannot dismiss
================================================

THE RULES, IN ONE BREATH

    Buzzes 5 minutes straight, then nag-bursts until the 20-minute deadline.
    To stop it you must DO A TASK, not tap a button:
        OUTSIDE   hold the camera on your surroundings for 12 s (it must be
                  bright, have sky or green in it, and actually move), then say
                  2 English sentences the app picked for you.
        INSIDE    say 3 sentences, one minute apart, each a different one.
    No photographs. No audio kept. The mic measures, the camera measures, and
    only a score + a level + a duration go into your journal.

    Blow the deadline without starting a task   -> 20 HOURS locked (that is the
                                                    "you never even woke up" one)
    Fail the task in time                      -> strike ladder: 1 h, 2 h, 3 h …
                                                   strike 10 = 10 h
    Unpin / go home / reboot during a lockout   -> +15 min each attempt (capped),
                                                   and the leash drags the lock
                                                   screen back. Rebooting re-applies
                                                   the remaining time.
    Set the clock back during a lockout         -> caught against the app's own
                                                   timer: the time you "saved" is
                                                   added back onto the lockout, and
                                                   a rewind during a mission shortens
                                                   the mission window instead.
    Serve the time                             -> the same alarm is re-armed. You
                                                   still owe that wake-up.


RUN THE WEB BUILD (no npm install — zero runtime dependencies)

    node -v          # need v18+; if missing: nodejs.org
    cd uporpay       # into this folder
    node serve.js

Then open  http://localhost:5173

    port busy        node serve.js 8080
    stop server      Ctrl+C
    run the tests    npm install && npm test      # 62 tests, needs jsdom


FIRST THINGS TO CLICK

    1. Admin tab (bottom nav)  ->  PIN: 0000, then Enter
       God mode is on: no lockouts while you test. Every override is journaled.
       Enter ALSO exits the app (the exit key): anything live is disarmed, the
       ring service + leash + lock-task are released, scheduled alarms are left
       alone, and the exit is logged as "admin exit" with no strike and no win.
       Admin -> "Key exits the app" turns that off; the console also has an
       "Exit app now" button for when you are already inside.
    2. Home -> "Ring right now"          the takeover screen. one button. no snooze.
    3. "I'M AWAKE" -> Stay inside        hold the mic button and speak the line.
       (In Admin, switch on "Auto-pass" and "Ignore line gaps" to clear a whole
        mission from a laptop in a few seconds — or Settings -> Test mode, which
        also simulates proofs where the browser has no speech recogniser.)
    4. Admin -> "Blow the deadline now"  you get the lock screen. flip
       "No lockouts" OFF and repeat to see a real one.
    5. Admin -> "Preview lock 30 s"      sit in the lockout with no risk.
       The lock screen has a "Admin key" button: type 0000 + Enter and the
       lockout ends and the app closes (journaled, no strike). Wrong PIN does
       nothing. Change the PIN before you trust this with a real morning, or
       switch "Key exits the app" off in Admin.
    6. Home -> "90-second trial"         the whole loop, hands-free.

    Camera and mic need a secure context. On http://localhost they work with no
    certificate setup. To test on a phone over wifi:
        node serve.js --https        then the printed https://<lan-ip>:5173
    or on Android:  adb reverse tcp:5173 tcp:5173  -> http://localhost:5173


THE APK (this is the one that can actually hold your phone)

    builds/wake-or-lock-debug.apk        in this repo, ~4.4 MB, debug-signed
    size + sha256                        builds/SHA256SUMS.txt (CI rewrites it
                                         next to every build)
    which commit it is                     versionName 1.0.<CI run>+<sha7>, and
                                         Settings -> Data on this device prints it too
    (the repo is private: sign in to GitHub to download from the web UI, or
     gh api repos/iambesttttduhh/uporpay/contents/builds/wake-or-lock-debug.apk \
       -q .content | base64 -d > wake-or-lock-debug.apk
     or the prerelease "wake-or-lock-debug", which CI attaches to on a
     v* tag / the workflow's publish input (see docs/APK.md))

    1. Copy it to the phone (cable, Drive, whatever) and open it.
       Allow "install unknown apps" for whatever you opened it with.
    2. Open the app once. It asks for: notifications, alarm & reminders,
       camera, microphone, and (optionally) "display over other apps".
    3. Set an alarm 2 minutes out. Lock the phone. Watch it take over.
    4. Demo timing is ON by default so the whole loop takes a minute —
       Settings -> Demo timing OFF once you believe it.

    What you get out of the box: full-screen takeover over the lock screen, a
    foreground service that keeps ringing when the app is swiped away, a 12-second
    leash loop that bills escape attempts and re-opens the lock screen, and a
    reboot that comes back into the same lockout.

    What you only get with one extra adb command: a device-owner lock-task, where
    Android itself refuses to leave the app — no Unpin button at all, and uninstall,
    safe boot, factory reset, adb debugging and editing the clock are all blocked
    while it runs (the power button stays Android's: a hard reboot always works, the
    lockout just resumes afterwards):

        adb shell dpm set-device-owner com.uporpay.wakeorlock/.AppDeviceReceiver

    (run once, and the app must be uninstalled first if it was already installed;
    see docs/DEVICE_OWNER.md — that is the difference between "very hard to get out
    of" and "the OS will not let you out".)

    Rebuild it: push this folder to GitHub -> Actions -> "Android APK" -> Run
    workflow, and download wake-or-lock-debug.apk from the run's artifacts (the
    workflow also commits it into builds/). Locally it needs JDK 17 + Android SDK:
        npm ci && npm run android:apk
    then android/app/build/outputs/apk/debug/app-debug.apk

    From this folder as a web server, the two files are also downloadable:
        /builds/wake-or-lock-debug.apk        the installable app
        /wake-or-lock.zip                     this folder + the APK (106 files, 4.1 MB)
    rebuild the zip with:  npm run zip

    Docs: docs/APK.md (permissions, what is native)
          docs/DEVICE_OWNER.md (the exit-button-less version)
          docs/NATIVE.md (how the pieces fit)


EVERYTHING STAYS ON THE DEVICE

No server, no account, no analytics — and nothing to leak anyway: no image file
is ever written, no audio is recorded, and backups are excluded so an old
snapshot cannot be restored to unlock a current lockout.
